# E1-18 · Benchmark y métricas

**Rol:** IA · **Depende de:** E0-06, E1-14

## Objetivo
Ejecutar el benchmark de desarrollo, guardar todas las salidas y calcular las métricas de la sección 9.1.

**Por qué importa:** Las métricas con numerador, denominador y fallos son evidencia directa para la rúbrica y el pitch.

## Punteros de contexto
- PDF sección 9.1
- `docs/protocolo_evaluacion.md` (definición exacta de cada métrica)
- `benchmark/benchmark_dev.jsonl`
- `eval/run_benchmark.py`, `eval/metricas.py`

## Restricciones
- Nunca leer el conjunto reservado; pero el runner acepta `--archivo <ruta> --salida <carpeta>` para que **el jurado** lo corra sin internet, sin copiar el archivo al repositorio (D-71)
- Reportar numerador, denominador y los IDs de los fallos; nunca solo porcentajes
- La validez de sustento requiere revisión humana: generar la muestra, no juzgarla

## Listo cuando
- `poetry run python -m eval.run_benchmark --split dev` guarda cada salida en `outputs/benchmark/`
- `poetry run python -m eval.run_benchmark --archivo tests/fixtures/benchmark_ejemplo.jsonl --salida /tmp/eval` funciona con red deshabilitada (simula la evaluación reservada)
- El README tiene la sección 'Evaluación reservada (para el jurado)' con el comando exacto
- `outputs/metricas.json` incluye: cobertura de citas, abstención correcta, abstenciones incorrectas, latencia p50 y p95, tokens y costo; **toda proporción con su n e intervalo de confianza del 95 % (bootstrap)** (D-57)
- `docs/ia_vs_baseline.md` (D-66): para clasificación, agrupación, búsqueda y ranking, la métrica de la IA y del baseline con intervalos, **dónde gana la IA y dónde no**, con 3–5 ejemplos de cada caso
- `docs/modelos.md` (D-67): ficha de cada modelo (embeddings y LLM) con proveedor, versión o tag, uso, parámetros, costo medido (USD y tiempo de cómputo; USD 0 si es local), consumo de memoria y limitaciones observadas
- `outputs/revision_sustento.csv` con 30 afirmaciones elegidas al azar (semilla fija) y la columna `veredicto` (sustentada · parcial · no sustentada · tipo incorrecto), para que la revise alguien que no escribió el código de generación; al completarse, `poetry run python -m eval.sustento` calcula la validez con su intervalo de confianza
- `poetry run pytest -v` pasa completo y se hizo la revisión de `docs/REVISION.md`.
