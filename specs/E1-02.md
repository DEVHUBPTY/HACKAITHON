# E1-02 · Carga, validación y reporte de calidad

**Rol:** D · **Depende de:** E0-04

## Objetivo
Leer los archivos del snapshot, validar IDs, URLs, fechas, campos obligatorios y nulos, separar las filas inválidas **sin detener la carga** y emitir un reporte de calidad.

**Por qué importa:** Es la etapa 1 del flujo del reto y cubre T01. Todo lo demás depende de datos limpios.

## Punteros de contexto
- PDF sección 3 (etapa 1 · Cargar), sección 7 y T01
- `src/carga.py`
- `tests/fixtures/t01_*.csv`
- `config/reglas_v1.3.yaml`

## Restricciones
- Validación tabular con pandera en modo *lazy*; registros JSON/GeoJSON con pydantic (D-19)
- Campos críticos (ID, URL, título, al menos una fecha) invalidan la fila; un campo opcional vacío solo se marca como nulo
- Un parser de fechas por fuente (formato GDELT, RFC 822 del RSS, milisegundos de USGS)
- Nunca convertir nulos en cero; un `valor` nulo en indicadores es válido
- No modificar `data/raw/`
- Cada fila rechazada lleva su motivo
- El reporte incluye distribución por medio e idioma (riesgo R-10)

## Listo cuando
- `poetry run python -m src.carga` genera `data/processed/`, `outputs/errores.csv` y `outputs/reporte_calidad.json`
- El reporte muestra válidos, rechazados y nulos por campo y por archivo
- `poetry run pytest tests/test_t01_carga.py` pasa: el fixture con errores se carga parcialmente sin excepción
- Los nulos de indicadores se conservan (mismo conteo antes y después)
- `poetry run pytest -v` pasa completo y se hizo la revisión de `docs/REVISION.md`.
