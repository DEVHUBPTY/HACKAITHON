# E1-20 · Reproducibilidad de punta a punta

**Rol:** IA + D · **Depende de:** E1-18

## Objetivo
Un solo comando que reconstruye todo desde `data/raw/` y comprueba que el resultado es idéntico a la ejecución registrada.

**Por qué importa:** La sección 7 se llama 'Contrato de datos y reproducibilidad' y la rúbrica premia 'código reproducible'; el jurado debe poder repetir la ejecución y obtener lo mismo (D-65).

## Punteros de contexto
- PDF secciones 7, 9.1 y 10
- `data/manifest.json`, `docs/parametros.md`

## Restricciones
- `poetry run python -m scripts.reproducir` ejecuta en orden: validación, normalización, limpieza, clasificación, agrupación, contexto, puntaje, fichas, benchmark y métricas
- Semillas fijas en `config/` para todo lo aleatorio (muestra de etiquetado, bootstrap, clustering si aplica) y registradas en `docs/parametros.md`
- El manifest guarda el **SHA-256 de las salidas deterministas**: `processed/`, tabla de grupos y puntajes, `fichas.jsonl` sin el texto del borrador, `metricas.json`
- El texto del LLM se reproduce **desde la caché**; sin caché puede variar, y eso se declara como limitación
- Versiones de modelo de embeddings, modelo LLM, reglas, prompts y commit registradas en cada ejecución

## Listo cuando
- Ejecutar `scripts.reproducir` dos veces sobre el mismo `raw/` produce los mismos hashes de salidas deterministas
- `scripts.reproducir --verificar` compara contra el manifest y reporta cualquier diferencia
- El README explica cómo reproducir en una máquina nueva con `poetry install` y un solo comando
- `poetry run pytest -v` pasa completo y se hizo la revisión de `docs/REVISION.md`.
