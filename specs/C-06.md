# C-06 · Casos de demostración por caso de uso

**Rol:** P + D · **Depende de:** E1-16

## Objetivo
Preparar los 5 casos de la demo (uno por caso de uso), su base de datos de demo, la caché de borradores, las capturas de respaldo y la verificación offline.

**Por qué importa:** El PDF exige 5 fichas trazables (una con evidencia insuficiente), una demo de 4 minutos sin depender de fuentes en vivo y respuestas a las pruebas dinámicas del jurado (D-52, D-55).

## Punteros de contexto
- PDF sección 4 (CU-01 a CU-05), sección 5 (evidencias mínimas) y sección 11 (pitch y pruebas dinámicas)
- `docs/demo.md`
- `tests/fixtures/` (casos sintéticos)
- Tecnologías (D-55): SQL en DuckDB, Playwright para Python, `st.query_params` de Streamlit, variables `HF_HUB_OFFLINE` y `TRANSFORMERS_OFFLINE`

## Restricciones
- `scripts/buscar_casos.py`: consultas SQL en DuckDB que proponen candidatos reales por CU (CU-01: P ≥ 70 con evidencia insuficiente; CU-02: economía con vínculo `IND-`; CU-03: menos procedencias que medios; CU-04: contradicción abierta; CU-05: logística/Canal)
- Si no hay un candidato real, se usa un caso sintético de `tests/fixtures/` con ID `SYN-`, `origen = sintetico` y una insignia **SINTÉTICO** visible en la app y en Notion
- `scripts/preparar_demo.py` crea `data/demo.duckdb` = snapshot + casos sintéticos elegidos; **nunca se usa para métricas**
- `scripts/calentar_cache.py` genera y guarda en caché los borradores de los 5 casos
- App en modo demo: atajos `?caso=CASO-00X` con `st.query_params` y una barra lateral con los 5 pasos del recorrido
- `scripts/capturas_demo.py` toma con Playwright una captura por paso del guion en `docs/demo/capturas/`, para Notion y como plan B
- `scripts/verificar_offline.py`: con `HF_HUB_OFFLINE=1` y `TRANSFORMERS_OFFLINE=1`, comprueba embeddings en caché, Ollama local, caché de borradores y base de demo
- Playwright se agrega como dependencia de desarrollo (`poetry add --group dev playwright` y `poetry run playwright install chromium`), antes del evento
- Respaldo extra opcional: grabación de pantalla del recorrido completo (QuickTime en macOS)
- Las 5 fichas se exportan a Notion con E1-16; CASO-004 es la de evidencia insuficiente

## Listo cuando
- `poetry run python -m scripts.buscar_casos` lista candidatos por CU con su ID y motivo
- Los 5 casos elegidos están en `docs/demo.md`, marcados como reales o sintéticos
- `poetry run python -m scripts.verificar_offline` termina en verde con Wi-Fi apagado
- `docs/demo/capturas/` tiene una captura por paso del guion
- Las 5 fichas están en la base *Casos y evidencias* de Notion
- Ensayo completo cronometrado en ≤ 4:00, registrado en la Bitácora
- `poetry run pytest -v` pasa completo y se hizo la revisión de `docs/REVISION.md`.
