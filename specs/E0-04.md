# E0-04 · Extracción de datos y manifest

**Rol:** D · **Depende de:** E0-01

## Objetivo
Construir **nosotros** el snapshot (D-74): scripts reproducibles que descarguen las fuentes A (TVN RSS + GDELT DOC 2.0), B (Banco Mundial API v2) y C (USGS), las conviertan al contrato de datos, generen `data/manifest.json` con SHA-256 y lo congelen. `validar_snapshot` lo verifica contra la receta de la sección 6.

**Por qué importa:** El reto exige un snapshot congelado y reproducible (T10, catálogo, sección 7). Si la organización entrega el snapshot, estos scripts quedan como la receta documentada.

## Punteros de contexto
- PDF secciones 6, 7 y 12
- `docs/fuentes.md` (URLs, parámetros y condiciones de cada fuente)
- `CLAUDE.md` → Contrato de datos y Reglas de datos
- Herramientas (D-24): `feedparser` para el RSS de TVN; `requests` directo a la API DOC 2.0 de GDELT (`mode=ArtList`, `format=json`), a la API v2 del Banco Mundial y al servicio FDSN de USGS (`format=geojson`)
- `config/fuentes.yaml` (consultas, países, indicadores, caja geográfica, ventana de fechas)

## Restricciones
- Se planificó para antes del evento (D-74); se registra con la fase en que realmente se hace: 'Preparación' antes del evento y 'Evento' desde que empezó, el 2026-10-06 (D-58)
- Volúmenes de A (metas de la sección 6): **200 noticias únicas**, mínimo operativo **100**, con **al menos 20 de TVN**
- Ventana de A: los 30 días previos a la extracción; si no se alcanza el mínimo, ampliar hasta 90 días y **registrar la cobertura efectiva** (fecha inicial y final reales) en el manifest
- Consultas de GDELT (D-83): cada tema (logística, turismo, economía y eventos naturales) en dos patas: medios de Panamá (filtro de país con términos en español, sin repetir "Panamá") y medios internacionales con frases específicas sobre Panamá. Términos en `config/fuentes.yaml`, registrados en el manifest; los crudos de las consultas anteriores quedan intactos en `raw/`, no alimentan `noticias.csv` y el manifest los declara como consultas históricas y registros excluidos
- GDELT devuelve máximo 250 artículos por consulta: dividir por rangos de fechas y deduplicar por URL
- GDELT DOC **solo cubre ~3 meses hacia atrás**: no pedir ventanas fuera de esa cobertura (R-27); `socialimage` no se guarda
- Banco Mundial con `per_page=1000` para evitar la paginación
- El RSS de TVN **no conserva todo el histórico** (sección 7): descargarlo **a diario** desde ya y acumular, para llegar a las 20 noticias de TVN (D-74)
- El campo `tema` de `noticias.csv` es el **tema de origen** (término de consulta de GDELT o categoría del RSS), nunca el del clasificador (D-62)
- `manifest.json` incluye un **historial**: versión, fecha, cambios de fuente, revisiones de datos detectadas y registros excluidos con su motivo; y `data/CHANGELOG.md` lo resume en texto (D-63)
- Generar `fuentes.json`: un registro por medio con dominio, nombre legible, país, origen (TVN RSS · GDELT) y condiciones de uso conocidas ('Pendiente de verificar' si no se conocen)
- `seendate` de GDELT → `fecha_deteccion`; nunca a `fecha_publicacion`
- Banco Mundial: una consulta por indicador; completar la cuadrícula de 540 filas (6 × 6 × 15; el PDF dice 1.350, ver D-81) con `valor` nulo
- USGS: 2024-01-01 a 2024-12-31, latitud 5–12, longitud −86 a −76, magnitud mínima 3; todos los eventos devueltos
- Ventana de noticias (D-74): la de la sección 6 (30 días previos a la extracción, ampliable a 90), compatible con la cobertura de GDELT. El intervalo [2024-01-01, 2025-10-01) de la sección 7 no se aplica porque es imposible de extraer hoy; se documenta como inconsistencia del PDF en el manifest
- Guardar respuestas crudas sin modificar en `data/raw/`
- No descargar cuerpos de artículos, imágenes ni videos
- La fuente D (SBP) es manual y no entra aquí (E3-02)

## Listo cuando
- `poetry run python -m scripts.extraer --todo` genera `data/raw/` y los archivos del contrato en `data/processed/`, incluido `fuentes.json`
- `poetry run python -m scripts.validar_snapshot` revisa cualquier snapshot (propio o de la organización) contra la receta: volúmenes de A (total y TVN), cobertura efectiva, cuadrícula de 540 filas, caja y fechas de USGS, campos del contrato; y lo reporta en `outputs/validacion_snapshot.json`
- `poetry run python -m scripts.manifest` escribe `data/manifest.json` con version, fecha_corte_UTC, consultas, cantidad por archivo, licencias, sha256 y transformaciones
- Ejecutar `scripts.manifest` dos veces sobre el mismo `raw/` produce el mismo hash
- `indicadores.csv` tiene exactamente 540 filas (D-81)
- Test: `validar_snapshot` falla si el manifest no tiene historial o si falta algún campo mínimo del contrato
- Test que verifica columnas del contrato en cada archivo
- `poetry run pytest -v` pasa completo y se hizo la revisión de `docs/REVISION.md`.
