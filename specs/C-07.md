# C-07 · Paquete de entrega y auditoría final

**Rol:** D + P · **Depende de:** C-06

## Objetivo
Armar los entregables de la sección 10 (repositorio, paquete de datos redistribuible y respaldo de Notion) y correr una auditoría automática de las condiciones previas antes del cierre.

**Por qué importa:** Las condiciones previas de la sección 10 (demo ejecutable, fuentes declaradas, sin secretos, sin citas falsas ni acciones prohibidas) se revisan antes del puntaje; si fallan, la entrega no se evalúa (D-72).

## Punteros de contexto
- PDF sección 10 (entregables y condiciones previas) y sección 5
- `docs/fuentes.md`, `docs/protocolo_evaluacion.md`
- Checklist de admisión en Notion

## Restricciones
- **Paquete de datos redistribuible:** `poetry run python -m scripts.empaquetar_datos` crea `entrega/datos/` con snapshot, diccionario, manifest, licencias y condiciones, y benchmark de desarrollo. **Excluye** todo contenido con redistribución restringida (descripción del RSS, `socialimage`, cualquier extracto); de esas fuentes se entregan solo metadatos y la **receta** (scripts de extracción y `docs/fuentes.md`)
- **Repositorio:** visibilidad y acceso del jurado según lo que indique la organización (privado con el jurado como colaborador, o público); archivo `LICENSE` para el código; el repositorio nunca incluye contenido protegido ni `data/demo.duckdb` con descripciones
- **Auditoría final:** `poetry run python -m scripts.auditoria_final` revisa: (1) secretos en el historial de git, archivos, capturas y exportaciones; (2) que toda afirmación de `fichas.jsonl` y de las exportaciones pase el validador; (3) que no exista ninguna acción, botón o estado 'publicar'; (4) que el paquete de datos no contenga campos restringidos; (5) que el README tenga instalación, comando de ejecución, pruebas y evaluación reservada; (6) que cada fuente usada esté en el Catálogo
- **PDF de respaldo** opcional: exportación del espacio Notion, guardada aparte; nunca reemplaza al espacio

## Listo cuando
- `scripts.empaquetar_datos` genera `entrega/datos/` y un test confirma que no contiene descripciones, `socialimage` ni extractos
- `scripts.auditoria_final` termina en verde; cualquier falla se registra en Notion antes de corregirla
- Instalación limpia en una máquina distinta: `git clone`, `poetry install`, comando de ejecución y `poetry run pytest -v` funcionan
- El Checklist de admisión y la Autoevaluación con la rúbrica están completos
- `poetry run pytest -v` pasa completo y se hizo la revisión de `docs/REVISION.md`.

## Resultados (herramientas construidas, primera corrida)

Esta entrega construye las herramientas y las corre una vez para saber qué falta; **la corrida final** es posterior a C-06, C-03/C-04, C-09, C-10 y C-11.

- `poetry run python -m scripts.empaquetar_datos` crea `entrega/datos/` (37 archivos, ≈ 0,85 MB, ignorado por git) y `outputs/entrega_manifest.json` (SHA-256 de cada archivo, versionado). Entra: snapshot (noticias solo con metadatos, fuentes, indicadores, eventos), manifest e historial, diccionario, licencias y condiciones, benchmark de desarrollo, receta de extracción, catálogo, fichas trazables, matriz de pruebas y página de métricas. El CSV de la SBP entra con `licencias/NOTA_SBP_D-116.md` (se retira con `paquete.sbp.incluir: false`). **Nunca entra:** `local.env`, `.duckdb`, crudos de RSS/GDELT/SBP, `data/revision*`, benchmark reservado, ni campos `descripcion`/`socialimage`/extractos/autor. El paquete se revisa entero después de construirlo; si algo prohibido llegó, se borra y sale con 1. `--verificar` revisa uno existente.
- `poetry run python -m scripts.auditoria_final` escribe `outputs/auditoria_final.md` y `.json`. Cada ítem es PASS, FALTA o NO VERIFICABLE AUTOMÁTICAMENTE, con su evidencia y cómo verificarlo. Sale con 1 si hay FALTA (`--estricto`: también con NO VERIFICABLE; `--reproducir`: corre `scripts.reproducir --verificar`).
- Todo en `config/entrega.yaml` (pydantic, sin claves extra). Tests: `tests/test_c07_entrega.py`.
